OVERVIEW

Tool flow

OVERVIEW

Notation used below

Point
p = i·225 + i′·15 + i″, one of 3,375 codeword bits; lin_to_pt converts.
Class k
A conjugate class: the orbit of spectral position J=(j1,j2,j3) under doubling mod 15. Size d ∈ {1,2,4}. 798 classes carry the 3,163 message bits; 53 are spectral nulls.
S_k
The class's GF(16) sub-message (4 bits), built from its d message bits.
Exponent
e = −(i·j1 + i′·j2 + i″·j3) mod 15. Class k adds Tr_d(S_k·α^e) to point p.
Trace mask
A 4-bit mask so that Tr_d(S_k·α^e) = parity(S_k AND mask). This is what turns a GF multiply into an XOR of 1 to 4 wires.
MODEL

model/bch3d.py

Golden model: field arithmetic, conjugate classes, and two independent encoders.

@dataclass ClassInfo

idx, rep, rep_lin, orbit, size, bit_offset, sub_masks, trace_masks, distinct_exps

One record per message-carrying class. Everything the RTL generators need lives here: where the class's bits sit in msg (bit_offset, size), how to build S_k (sub_masks), and which wires form each product (trace_masks[e]). distinct_exps is the computation class: 15, 5, 3 or 1 exponents over the whole cube.

BCH3DModel.__init__(N=15, T=2, prim_poly=0b10011)

Derives M from N = 2^M − 1 and builds the GF(2^M) exp/log tables by repeated multiply-by-α with reduction by the primitive polynomial. exp is doubled in length so exp[a+b] works without a mod. Then calls _build_classes and sets K (message bits) and N_CLASS.

mul(a, b) · sq(a)

GF(16) multiply and square through the log tables: exp[log a + log b], with 0 handled separately. Used by every encoder, by the trace masks, and by the TM rotation constant.

trace_d(a, d)

The subfield trace a + a² + a⁴ + … (d terms). Asserts the result is 0 or 1, which is the property that makes the IDFFFT output binary.

lin_to_pt(p) · pt_to_lin(pt)

Convert between the flat bit index and (i, i′, i″). This layout is the codeword bit order everywhere, including the RTL and the .mem files.

_in_null_cube(pt)

True if every coordinate is in 1..2T. Any class that touches this 4×4×4 cube is forced to zero (spectral null) and carries no message.

_build_classes()

Step 1
For every point, walk the doubling orbit. Keep it only if the point is the smallest linear index in its orbit (the insertion point), so each class is found once, in ascending order. This order must match the Verilog converter.
Step 2
Drop orbits that hit the null cube (53 for N=15, T=2).
Step 3
sub_masks: a size-d class stores d bits in GF(2^d) with basis γ^i, γ = α^(15/(2^d−1)); mask r lists which message bits feed bit r of S_k.
Step 4
distinct_exps: sweep all 3,375 points and collect the set of exponents. Result for N=15: 754 classes with 15, 30 with 5, 13 with 3, 1 with 1.
Step 5
trace_masks[e]: for each basis bit r of S_k, compute bit 0 of Tr_d(α^r·α^e). Because the trace is linear, the product for any S_k is the parity of the selected bits.

msg_to_submsg(msg_int)

Python twin of bch3d_msg_to_submsg.v: slice each class's bits out of the message and apply sub_masks. Returns 798 values in GF(16).

encode_idffft(msg_int) — golden path 1

Fills the full 15×15×15 spectrum: each class value goes to its insertion point and is squared as it walks the orbit (Frobenius conjugacy). Then runs a separable 3-D inverse transform: 1-D IDFT along each axis in turn. Asserts every output is 0 or 1. This path shares no code with the hardware formulas, which is why it is the reference.

encode_trace(msg_int) — golden path 2

Evaluates the hardware formula directly: for each point, XOR over all classes of parity(S_k AND trace_masks[e]). This is exactly what the baseline RTL does; agreement with path 1 proves the masks are right.

decode_dffft_check_nulls(cw_int)

Forward 3-D transform of a codeword, then checks the null cube is all zero. Confirms an output really is a codeword of the 3-D BCH code.

self_test()

For four (N, T) settings, compares the two encoders and the null check on all-0, all-1, single-bit and random messages. For N=15, T=2 it also pins K=3163, 798 classes, 53 null classes and the 754/30/13/1 computation-class histogram.

MODEL

model/bch3d_tm.py

Reference model of the time-multiplexed encoder.

encode_tm(m, msg) → (codeword, slices)

  1. Start from the sub-messages S and precompute one constant per class: step = α^(−j3).
  2. For cycle c = 0..14 (this is i″), each of the 225 trees (i, i′) uses the fixed exponent e0 = −(i·j1 + i′·j2), the same in every cycle.
  3. After the cycle, multiply every S_k by its step. Then S_k(c) = S_k·α^(−c·j3), so Tr(S_k(c)·α^e0) is the full-cube term at (i, i′, c).

This is the idea behind design 3: a per-class register update replaces a 15:1 mux in front of every tree input.

self_test()

Checks encode_tm against encode_idffft: all unit vectors for N=7, and random plus all-0/all-1 for N=15.

MODEL

model/bch3d_cse.py

Study of XOR sharing between output points (not used to generate RTL).

normals_n15()

Lists order-15 normal vectors n in Z₁₅³ by pairing projective points of F₃³ and F₅³ through the Chinese remainder theorem.

build_groups(m)

Greedy cover: repeatedly picks the normal whose plane J·n = 0 holds the most uncovered classes. For classes in one plane, the partial XOR is the same along every line in direction n, so it only needs 225 values instead of 3,375.

key_of(p, n)

Canonical representative of point p modulo the line ⟨n⟩: the smallest of its 15 shifts. Points with the same key share a partial sum.

encode_cse(m, msg, groups)

Encodes with the grouped sums: 225 partial values per group, then one XOR per group at each output. Checked against the golden model.

cost(m, groups) · main()

cost counts XOR2 gates and a LUT6 estimate (5 inputs merged per LUT) for both levels. main prints the comparison against the per-point trees and runs the check on 8 messages.

GENERATOR

model/gen_rtl.py

Writes every encoder, wrapper and testbench as Verilog text from the model.

_xor_expr(terms) · _s_mask_expr(s, mask, M) · _s_mask_off(s, off, mask, M)

Small string builders. _xor_expr joins terms with ^ and wraps long lines. _s_mask_expr turns a 4-bit trace mask into s[0] ^ s[2]. _s_mask_off does the same with a bit offset, e.g. S[20] ^ S[23] for class 5, because Verilog cannot index a part-select.

generate_baseline_rtl(m, out_path) → design 1

  1. For each of the 3,375 points, list the sub-message bits selected by trace_masks[e] for every class: this inlines all 798 multipliers for that point.
  2. Emit one module bch3d_base_pt_*_w<width> per distinct input width, each just ^in_bits.
  3. Top bch3d_enc_baseline: the converter, then one point instance per codeword bit. Separate instances stop synthesis from sharing multipliers between points, which is what "no optimisation" means here.

slice_points(m, plane) · base_slice_mod_name(m) · generate_baseline_slice_reg_rtl(m, out_path, plane=0)

slice_points returns the 225 linear indices with i″ = plane. The slice generator writes the same per-point units as the baseline, only for those points, with msg registered on input and the 225 outputs registered on output. It exists so a 1/15 piece of design 1 can be placed and routed to estimate the full design.

generate_baseline_slice_testbench(m, tb_path, n_vecs, msg_mem, cw_mem, plane=0)

Pipelined check: a new vector every cycle, and two cycles later the slice is compared with the matching 225 bits picked out of the golden codeword ({cw[p_224], …, cw[p_0]}).

generate_reg_wrapper_rtl(m, core, out_path) · generate_reg_wrapper_testbench(…)

Writes <core>_reg: an input register on msg, the combinational core, an output register on codeword. Designs 1 and 2 have no flip-flops, so without this Vivado has no register-to-register path to time. The testbench feeds one vector per cycle and checks the codeword two cycles later.

generate_opt_rtl(m, out_path) → design 2

  1. Give every (class, exponent) pair in distinct_exps a wire in mul_out: 11,500 wires in total.
  2. Emit one multiplier-unit module per distinct (size, exponents) signature; each output is a trace-mask XOR of the 4 input bits.
  3. bch3d_mul_bank_* instantiates one unit per class: the shared bank, 4,597 LUTs.
  4. Top bch3d_enc_opt: for each point, pick the one bank wire per class that matches its exponent, and XOR the 798 picks in bch3d_xor_tree_*.

Each product is computed once and fanned out ("compute once, route many"). The 3,375 trees of 798 inputs remain, about 540,000 LUTs.

tm_mod_name(m) · tm_asm_mod_name(m)

Module names: bch3d_enc_tm / bch3d_enc_tm_asm for N=15, T=2, with an _nX_tY suffix otherwise.

generate_tm_rtl(m, out_path) → design 3 core, returns bank wire count

  1. Pruned bank: only exponents reachable at i″=0 get a wire (10,608 instead of 11,500), since the rotation of S supplies the i″ part.
  2. Rotation: for each class, the constant g = α^(−j3) is written as a 4×4 bit matrix (columns α^r·g), so S_rot bit q is an XOR of some S bits. Wiring only when j3 = 0.
  3. 225 trees: tree (i, i′) reads wire e0 = −(i·j1 + i′·j2) of each class, always the same wire.
  4. Control: busy, 4-bit cyc, accept = start && (!busy || last) so a new message can start in the last busy cycle. On accept S loads the sub-message; otherwise it rotates.
  5. Outputs: slice, slice_idx and slice_valid are registered; done marks slice 14.

generate_tm_asm_rtl(m, out_path)

Wraps the TM core to give a full codeword. cw_sr has 225 groups of 15 bits; group g shifts in slice[g] whenever slice_valid is high, so after 15 slices bit g·15 + c holds point (i, i′, c), which is already the flat codeword order. One cycle after the last shift (done_d) the hold register codeword loads, and cw_valid pulses. No LUTs, only flip-flops and an enable.

generate_tm_testbench(…) · generate_tm_asm_testbench(…)

Clocked testbenches. Both run a gapped pass, a back-to-back pass (one codeword per 15 cycles) and a reset in mid-run, and scramble msg right after start to prove it is latched. The TM bench rebuilds the codeword from slices and also compares with bch3d_enc_opt. The asm bench checks cw_valid is done delayed by two and that codeword holds for 15 cycles.

generate_testbench(m, tb_path, vec_dir, num_random, include_all_unit_vectors) → (n_vecs, msg_mem, cw_mem)

  1. Builds the codeword of every unit vector quickly: a single message bit touches one class, so only that class's 15 point masks matter.
  2. fast_encode XORs unit codewords together (the code is linear over GF(2)) and is checked against encode_idffft and the null check.
  3. Writes msg_*.mem and cw_*.mem: all-0, all-1, all 3,163 unit vectors and random messages. Passing every unit vector proves the circuit correct for all 2^3163 messages.
  4. Writes a combinational testbench for designs 1 and 2 with ONLY_BASE/ONLY_OPT switches.

main()

Parses --n --t --rtl-dir --tb-dir --vec-dir --num-random, then writes in order: baseline, opt, TM core, vectors and testbench, TM and asm testbenches, the two register wrappers and their benches, and the baseline slice and its bench.

RTL

rtl/bch3d_msg_to_submsg.v

Hand-written, parameterised by N, T, PRIM_POLY; all tables computed at elaboration.

log2_np1(n) · alpha_pow(e)

log2_np1 gives M from N. alpha_pow computes α^e in the polynomial basis by shifting and reducing, the same as the Python table.

dbl · next_pt · in_null_cube · orbit_size · is_rep · orbit_is_null · count_classes · count_bits

The class search from _build_classes, rewritten as Verilog constant functions on the linear index: one doubling step, orbit length, "is this the smallest member", "does the orbit touch the null cube". count_classes and count_bits give N_CLASS = 798 and K_BITS = 3163, which size the ports.

build_table() · sub_mask(r, d)

build_table packs, per class, its bit offset and size into one wide constant. sub_mask is the Verilog version of sub_masks: which of the class's d bits feed bit r of S_k.

generate block g_cls / g_bit

For each class and each of the 4 output bits: sub_msg[4k + r] = ^(msg[OFF +: SZ] & MASK). For size-4 classes this is plain wiring; for size 2 and 1 a few XORs. Synthesises to 0 LUTs for N=15, T=2.

SCRIPTS

scripts/

Testbench for the converter, simulation and Vivado flows.

gen_tb.py: model(N, T, poly) → (M, K, NC, enc)

A third, independent implementation of the converter in a few lines, used to write tb/tb_bch3d_msg_to_submsg.v for four (N, T) settings with directed and random messages.

sim.ps1 -Top -Files [-WorkDir] [-Defines] [-Glbl]

Runs xvlog → xelab → xsim -R. -Glbl elaborates work.glbl for post-route netlists. Exit code 0 only if the log contains PASS and no FAIL/ERROR/MISMATCH.

vivado_ooc.tcl <top> <part> <flatten> <out_dir> <files…>

Out-of-context synthesis only: utilisation reports, a LUT-cell summary line, an optional pre-route timing report (CLOCK_PERIOD_NS) and an optional functional netlist (WRITE_FUNCSIM=1).

vivado_pnr.tcl <top> <part> <period> <flatten> <out_dir> <files…>

Synthesis, create_clock, 20% input/output delays, opt_design, place_design, route_design (no phys_opt_design: it crashed Vivado on the 4 ns run). Writes timing, critical-path, utilisation, fanout, route-status, power, congestion and clock reports, a routed checkpoint, an optional routed netlist (WRITE_TIMESIM=1), and prints PNR_SUMMARY with WNS and WHS.
