Time-Multiplexed 3-D BCH Encoder, Explained

How 3,375 codeword bits are produced by only 225 XOR trees that are reused over 15 clock cycles, and how the Verilog implements it.

Design status: frozen. bch3d_enc_tm (N=15, T=2), verified in RTL and on the post-route netlist; routed on xc7v2000t at 6 ns with 17,197 LUTs and 3,416 FFs. See the results section at the bottom.

1. The problem in one picture

The encoder turns a 3,163-bit message into a 15×15×15 cube of 3,375 code bits. In the earlier "optimised" design every one of the 3,375 cube points has its own XOR tree that adds up 798 one-bit contributions (one per message-carrying conjugate class). Those 3,375 trees are 540,000 LUTs, which is 99% of that design.

The time-multiplexed design computes the cube one 15×15 slice per clock cycle. The same 225 trees are used again on every cycle, and each cycle's output is the slice at a different third coordinate i''.

2. The trick: make the trees "see" a moving message

2.1 What each tree adds up

For every conjugate class k (798 of them) the model stores a 4-bit field element Sk, built from the message. Class k has a representative frequency (j1, j2, j3). The contribution of class k to code bit (i, i', i'') is a single bit:

Tr( Sk · αe )   with   e = −(i·j1 + i'·j2 + i''·j3) mod 15

The code bit is the XOR of these 798 bits. "Tr(·)" is just an XOR of a few bits of the 4-bit product, so the bank of all Tr(S·αe) values is a pile of small XORs.

2.2 Fix the cycle axis

Let the cycle be c = i'' and the tree be u = (i, i'). Then

e = −(i·j1 + i'·j2) − c·j3 = e0(u) − c·j3

The part e0(u) depends only on the tree, so it is fixed wiring. Only the term −c·j3 changes with the cycle. A field multiplication by α−c·j3 can be moved from the exponent onto S:

Tr( S·αe0 − c·j3 ) = Tr( ( S·α−c·j3 ) · αe0 )

So instead of routing a different bank wire to each tree every cycle (a 15-to-1 mux in front of 179,550 tree inputs, which would cost more LUTs than it saves), we keep a 4-bit register per class and update it every cycle:

Sk ← Sk · α−j3   (a constant multiplier: a few XORs; pure wiring if j3 = 0)

After c cycles the register holds S·α−c·j3, and every tree, still wired to the same bank wire e0(u), produces exactly the bit that belongs at (i, i', c).

3. The block diagram

Fully parallel part
Converter and multiplier bank are unchanged in function and always active. Only the input to the bank (S) changes each cycle.
Reused part
225 trees (36,000 LUTs before optimisation) are fed by the same wires every cycle. That is the saving.
Cost
One codeword every 15 cycles instead of every cycle. 3,192 FFs for S and 225 FFs for the output slice.

4. The wiring, concretely

The key point is that no wire ever moves. A tree's 798 inputs are tied once, at design time, to the bank wire for exponent e0(u) of each class. Here is one class (a "15-computation" class, so 15 bank wires) feeding three trees:

Each bank wire fans out to roughly 15.6 tree inputs on average (179,550 tree inputs over 11,500 wires). That fanout is what dominates routing delay: at 5 ns the worst path is 87% wire delay.

Special classes

  • j3 = 0 (for example class 0 and every class where the third frequency is zero): S_rot = S, so the register just holds its value (wires only).
  • j1 = j2 = 0 (classes 0 to 2 in the generated file): e0 is always 0, so they need only one bank wire, and all variation comes from the register rotation.
  • Small subfield classes (size 1 and 2): S stays inside GF(2) or GF(4) because j3 is 0 or a multiple of 5, so the 4-bit register can still be used with the same trace masks.

5. Control and timing

  • start may be pulsed for one cycle with a valid msg. The sub-message is latched into S, so msg may change right afterwards.
  • accept = start && (!busy || last). A new start is accepted when idle or in the very last busy cycle, so codewords can follow each other every 15 cycles with no gap.
  • The 225-bit slice output is registered, so slice_valid and slice_idx lag the internal state by one cycle. The testbench assembles cw[i*225 + i'*15 + slice_idx] = slice[i*15 + i'].
  • done = slice_valid && slice_idx == 14.
  • rst clears busy, cyc, slice_valid, slice_idx. The datapath (S, slice) is not reset because it is not observable while slice_valid is low.

6. Walking through the code

All RTL is generated by generate_tm_rtl() in model/gen_rtl.py, from the Python golden model (model/bch3d.py) and the TM reference model (model/bch3d_tm.py). The snippets below are real output (build/rtl/bch3d_enc_tm.v, N=15, T=2).

6.1 Generator: which bank wires exist

# only exponents reachable at i''=0 get a bank wire (10,608 instead of 11,500)
for c in m.classes:
    e0s = sorted({(-(ia*c.rep[0] + ib*c.rep[1])) % N for ia in range(N) for ib in range(N)})
    for e in e0s:
        wire_map[(c.idx, e)] = nw;  nw += 1

6.2 Bank: small XORs of S bits

module bch3d_tm_bank_n15_t2 (input wire [3191:0] S, output wire [10607:0] mul_out);
    assign mul_out[0]  = S[0];                  // class 0 alpha^0
    assign mul_out[1]  = S[7];                  // class 1 alpha^0
    assign mul_out[14] = S[20] ^ S[22] ^ S[23]; // class 5 alpha^9

The mask for each (class, e) pair is trace_masks[e] from the model: bit r of S is XORed in if the trace of αr·αe has bit 0 set. Class k owns S[4k +: 4].

6.3 Rotation: a constant GF multiplier per class

# generator
g    = m.exp[(-c.rep[2]) % N]                 # alpha^(-j3)
cols = [m.mul(1 << r, g) for r in range(M)]    # image of each basis bit
# output bit q = XOR of input bits r whose image has bit q set

// generated Verilog
assign S_rot[0] = S[0];            // class 0: j3 = 0  -> identity (wires)
assign S_rot[4] = S[4] ^ S[5];     // class 1: j3 = 1  -> real multiplier
assign S_rot[5] = S[6];
assign S_rot[7] = S[4];

6.4 Trees: fixed wiring, one instance per (i, i')

bch3d_tm_tree_n15_t2 u_tree_1_2 (
    .in_bits({mul_out[0], mul_out[1], mul_out[2], mul_out[3], mul_out[4], mul_out[18], ...}),
    .out_bit(slice_c[1*15 + 2]));

module bch3d_tm_tree_n15_t2 (input wire [797:0] in_bits, output wire out_bit);
    assign out_bit = ^in_bits;      // 798-input XOR, about 160 LUT6
endmodule

The first five inputs are the classes with j1 = j2 = 0 (a single wire each, same in every tree). The sixth onward changes from tree to tree because e0 differs.

6.5 State machine and datapath

wire last   = busy && (cyc == 4'd14);
wire accept = start && (!busy || last);

always @(posedge clk) begin
    if (rst) begin busy <= 0; cyc <= 0; slice_valid <= 0; slice_idx <= 0; end
    else begin
        slice_valid <= busy;                 // output stage lags by one cycle
        slice_idx   <= cyc;
        if (accept)        begin busy <= 1; cyc <= 0; end
        else if (last)     begin busy <= 0; cyc <= 0; end
        else if (busy)     cyc <= cyc + 1;
    end
    if (accept)    S <= sub_msg;             // latch the message
    else if (busy) S <= S_rot;               // rotate: S(c+1) = S(c) * alpha^-j3
    slice <= slice_c;                        // 225 tree outputs
end
assign done = slice_valid && (slice_idx == 4'd14);

6.6 Testbench

generate_tm_testbench() writes a clocked testbench that reads the same golden vectors as the other encoders. It runs three passes: gapped starts, back-to-back starts (one every 15 cycles, msg scrambled right after start to prove it was latched), and a reset in the middle of a codeword followed by a clean run. A monitor assembles the 15 slices and compares against the golden codeword and against bch3d_enc_opt.

7. Why it is correct

  • Algebra: the identity in 2.2 is exact for every field element, so S(c)·αe0 = S·αe (try the demo above).
  • Model: model/bch3d_tm.py matches the independent 3-D IDFFFT on all unit vectors (N=7) and random and all-0/all-1 messages (N=15).
  • RTL: xsim passes for N=7 T=1, N=7 T=2 and N=15 T=2 (all 3,163 unit vectors plus random ones), including back-to-back and reset tests.
  • Routed netlist: the post-route functional netlist (6 ns run) passes 324 sampled vectors with 0 errors. Because the encoder is linear over GF(2), the unit-vector tests cover all messages.

7b. Getting the whole codeword out: the assembly wrapper

The core only streams slices. bch3d_enc_tm_asm wraps it and collects them. Think of the 3,375 bits as 225 small shift registers of 15 bits, one per tree (i, i'). Every cycle the tree's new bit enters at one end and the older bits move along. After 15 cycles the register for tree (i, i') holds that tree's bit for every i'', already in the right place of the flat codeword.

for each g = i*15 + i':
    if (slice_valid) begin
        cw_sr[g*15 +: 14] <= cw_sr[g*15+1 +: 14];   // shift towards bit 0
        cw_sr[g*15 + 14]  <= slice[g];               // new bit enters at the top
    end
// the bit from cycle 0 ends at position 0, cycle 14 at position 14: i'' = position
if (done_d) codeword <= cw_sr;                       // hold register, stable 15 cycles
cw_valid <= done_d;                                 // 1-cycle pulse, 2 cycles after done

No decoder or mux is needed, only flip-flops with a clock enable. The hold register matters for back-to-back use: without it, the shift groups start receiving the next codeword's first slice right after the last one, so the full codeword would exist for one cycle only. Cost: +6,784 FFs (10,200 total), LUTs unchanged (17,196). Routed at 6 ns: setup +0.062 ns, hold +0.081 ns; the critical path is now slice_valid driving the 3,375 clock enables.
